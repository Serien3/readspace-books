# 十三、论我们已经取得的成果

思考所设想的程序结构时，我常使用的一个比喻，是把程序看作由一颗颗珍珠串成的项链。

我们按层描述程序，每层都包含对上层假定可用实体的细化。细化或者是动态的，即算法；或者是静态的，即数据结构；它们都应由适当的机器来理解。我用“珍珠”指这样的机器，连同其所包含的细化。

上一节程序由六颗珍珠组成的项链构成，顺序为以下两者之一：

```text
COMPFIRST         COMPFIRST
CLEARFIRST        CLEARFIRST
ISCANNER          ISCANNER
COMPPOS           COMPPOS
LINER             LINER
LONGREP           SHORTREP
```

LONGREP、SHORTREP 是不同珍珠：它们将“上表面”的相同概念，解释为“下表面”的相同概念；仅具体细化不同。它们就像针对同一任务、同一机器的不同备选程序。

改变程序，将被视为用一颗或多颗其他珍珠，替换原项链中的一颗或多颗珍珠。珍珠是构成程序的独立单位。构造程序，作为构造相关程序类中的一个成员，现在被看作两阶段过程：先制作比严格所需更多的珍珠，再从其中选出一部分，串成一条匹配的项链。

## 13.1 为什么用珍珠作为修改单位

采用两阶段方法的理由很多。设计时必须考虑许多备选程序；程序完成后，还要将它改成其中一种。若把程序当作语言基本符号的线性串，并在同一层次将修改视为文本操作，那么每次修改，都必须在该语言可写出的所有程序——正确或错误的全部程序——这一全集中理解。难怪修改程序如此危险！

基本符号太小，也缺乏意义，不适合用来描述修改。珍珠体现独立设计决定，或者原问题陈述中一个隔离出的方面，其目的就是成为这种修改的自然单位。

换一种表述：ALGOL 60 诞生时，人们发现语法是表达程序文本结构的强大手段。语法受到如此推崇，以至许多同行把计算科学等同于语法分析！然而，人们稍稍忽略了：通过语法表达结构，结构只被十分间接地给出，必须对线性基本符号序列施加语法分析算法，才能导出。

意识到许多修改不影响大部分结构时，这就令人难受：费力地重新分析修改后的文本，最后同样的结构又出现了！我强烈感到，使用上下文无关方法表示结构的适用性，被严重高估了。

我身边有人给我看过这样一个 ALGOL 60 程序错误：一个程序在具备完整检查能力的实现上产生错误输出。该实现还要求，在程序最后一个 end 后，必须有最终的 progend；此附加符号在其他位置都不允许，以便确认 begin-end 配对正确。结果发现：

1. 程序某处漏了字符串的右引号。
2. 后面另一处漏了字符串的左引号。
3. 所得程序的 begin-end 结构在语法上正确。
4. 在两处遗漏之间声明的标识符，也只在这两处之间使用，因此连依赖上下文的检查也无法报警。

我原本就怀疑上下文无关方法是否足以表达宏观结构；见到这个错误时，竟很高兴！

越思考珍珠，越觉得：如果承认有责任为一个大型程序考虑例如一千种可能版本，那么类似珍珠的东西就是唯一出路。不能期望程序员把这一千个版本彼此独立地从头编写。

我能看到的唯一方法是组合技术：例如，造 250 颗珍珠，超过一条项链所需的 200 颗，再按特定选择串成项链。我看不到其他可行办法。另一种通过组合产生大量变化的机制是排列，但这里不能使用：最终必须是匹配的项链；给定珍珠后，能串成匹配项链的次序已经相当确定。而且，即使不唯一，允许的换序也基本无关紧要！

## 13.2 接口与概念的有效范围

珍珠还赋予只含项链上半部的“不完整”程序一个明确地位：它可以视为由适当机器执行的完整程序，而下半部给出这一机器的可行实现。因此，上半部的正确性可以不依赖下半部的具体选择而确立。

在相邻珍珠之间，可以作一个“切口”。它是一份机器手册：切口下方的项链提供该机器，切口上方所表示的程序使用它。手册是两部分之间的接口。我们觉得，这种接口比把数据表示看作操作之间接口的方式更有帮助，尤其有助于保证程序调整所需的组合自由。

还要谈概念沿项链的有效范围。例如，image 在最上面的 COMPFIRST 中引入，在倒数第二颗 LINER 中通过解释被消解。如果认定所设想程序需要太多存储空间，无法容纳 image，那么就必须作重大修改：用其他珍珠替换最上面五颗，因为它们就是 image 概念的有效范围！但底部珍珠，无论 LONGREP 还是 SHORTREP，都可以保留。此例说明，珍珠替换绝不限于底部。

关于概念的有效范围，有一项观察，第一次作出时令我十分激动。回头看相当显然，恰因此，值得明确说出。每颗珍珠对应“一个独立设计决定”，珍珠次序也就意味着决定的次序。能改变这一次序吗？能，但会得到不同的珍珠。

作为实验，我遵循一条熟悉建议：面对两个基本操作，这里是 build 与 print，立即决定它们的接口，这里是 image，以便二者独立细化。我照做，得到以下项链：

```text
COMPFIRST
LINER′
CLEARFIRST′
ISCANNER′
COMPPOS′
SHORTREP
```

中间四颗加撇号，表示它们虽然体现原来相同的决定，却是不同的珍珠。所得程序杂乱得多。为什么？

沿项链，可以标出每个概念的有效范围。它们当然重叠；可以把它们看作编织整个解释的单根线，组成一条“逻辑绳索”。杂乱版本的逻辑绳索由更多、且有时更长的线编成；绳索更粗，整个构造的相互牵连更紧密。

这项观察令我激动，因为它至少对我非常有说服力地表明：优雅、清晰等等确实具有显著的数量因素。莫扎特就知道这一点：他许多令人屏息的作品，简单得让人误判，仿佛几乎什么材料也没用就作成了！

## 13.3 推迟表示决定带来的好处

更技术地说，加撇号的版本杂乱，是因为过早把 image 解释为行，迫使 CLEARFIRST、ISCANNER、COMPPOS 都用行来解释；而本来还可以用图像来解释它们，也就是独立于具体表示。

换句话说，原版本比加撇号版本更审慎地利用了抽象能力。独立于具体表示的珍珠越多，程序就越容易调整，也越容易理解，因为那组珍珠可以在更高抽象层次理解。

这一经验似乎使可适应性和清晰性的目标获得了某些实质内容；更进一步，二者本质上相辅相成。这很令人鼓舞，虽并不令人惊讶。

这也至少让我更清楚地看到当前努力的范围。无论发展出什么，都不会成为一个通用问题求解器；既不是机械的，也不是写给人类问题求解者的那种。不过，当人成功找到解法时，它或许能帮助理解解法“优雅”的不同方面；因此，也可能提供某种指导。
